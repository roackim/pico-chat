  #### The design principles worth stealing                                                                                                                                                                                                                                                
                                                                                                                                                                                                                                                                                           
  1. Everything is a message; control flow is exceptions.                                                                                                                                                                                                                                  
  There are exactly 6 exception types (exceptions.py), all subclasses of InterruptAgentFlow(*messages). Completion, timeout, cost-limit, and format-error are not return codes or flags — they're raised with the exit message already attached. The loop just appends e.messages and      
  breaks on role == "exit". This collapses a dozen branching paths into one try/except/finally.                                                                                                                                                                                            
                                                                                                                                                                                                                                                                                           
  2. Linear history = trajectory.                                                                                                                                                                                                                                                          
  self.messages is the single source of truth. There's no separate "trajectory" object; what you pass to the LM is the trajectory. Every action, observation, error, and cost is a message with an extra dict. This makes debugging, replay, fine-tuning, and serialization trivial        
  (serialize() just dumps self.messages).                                                                                                                                                                                                                                                  
                                                                                                                                                                                                                                                                                           
  3. One tool: bash. No ls/read/write/edit tools. The LM shells out for everything. This is the single biggest reason it generalizes — it works with any model (even ones without native tool-calling, via regex parsing) and needs zero package installs in sandboxes.                    
                                                                                                                                                                                                                                                                                           
  4. `subprocess.run` per action, not a persistent shell.                                                                                                                                                                                                                                  
  Each command runs in a fresh subshell (local.py). Deliberately kills the whole process group on timeout so nothing is orphaned. This is why they call it "a big deal" for stability and sandboxing — you literally swap subprocess.run for docker exec and scaling is free. The prompt   
  explicitly tells the model that env/dir changes don't persist, and shows the VAR=x cd /dir && ... pattern to work around it.                                                                                                                                                             
                                                                                                                                                                                                                                                                                           
  5. Two interchangeable action parsers.                                                                                                                                                                                                                                                   
  - actions_toolcall.py — native tool calls (v2 default, recommended)                                                                                                                                                                                                                      
  - actions_text.py — regex on  mswea_bash_command ` blocks (v1 / no-tool-call models)                                                                                                                                                                                                     
                                                                                                                                                                                                                                                                                           
  Both raise the same FormatError, so the agent loop doesn't care which one is in use. Swap model ↔ parser without touching the loop.                                                                                                                                                      
                                                                                                                                                                                                                                                                                           
  6. Format errors are recoverable, but bounded.                                                                                                                                                                                                                                           
  On a bad parse it re-prompts with a specific error (including why — e.g. finish_reason=length means truncation, so it tells the model to be more concise). max_consecutive_format_errors: 3 stops infinite loops. Note the subtle detail: the API call was billed before parsing failed, 
  so it manually adds the cost back from e.messages[0].extra.cost.                                                                                                                                                                                                                         
                                                                                                                                                                                                                                                                                           
  7. Output truncation is handled in the prompt layer.                                                                                                                                                                                                                                     
  The observation template elides outputs >10k chars (head 5000 + tail 5000 + "N chars elided") and tells the model how to get more (head/tail/sed/redirect-to-file). Keeps context bounded without a separate compaction mechanism.                                                       
                                                                                                                                                                                                                                                                                           
  8. Config is data, not code.                                                                                                                                                                                                                                                             
  YAML holds all templates (system, instance, observation, format-error), limits, env vars. Templates use Jinja2 with StrictUndefined. This is where much of the benchmark performance actually lives — the prompt engineering (recommended workflow, sed examples, macOS sed -i ''        
  special-case, the COMPLETE_TASK_AND_SUBMIT_FINAL_OUTPUT submit marker) is just a string you can A/B without touching Python.                                                                                                                                                             
                                                                                                                                                                                                                                                                                           
  #### Notable details                                                                                                                                                                                                                                                                     
                                                                                                                                                                                                                                                                                           
  - Submit protocol: task done = model runs echo COMPLETE_TASK_AND_SUBMIT_FINAL_OUTPUT; _check_finished() detects it and raises Submitted with the submission payload.                                                                                                                     
  - Retry (retry.py): tenacity, exponential backoff (4–60s), 10 attempts, but aborts immediately on auth/context-window/unsupported-param errors rather than wasting them.                                                                                                                 
  - Cost tracking is first-class: per-call cost on every message's extra, global accumulator, cost_limit enforced in query().                                                                                                                                                              
  - Sandboxing is just another Environment: local, docker, singularity, bubblewrap, contree — same execute() interface.                                                                                                                                                                    
                                                                                                                                                                                                                                                                                           
  #### What I'd take away for our harness                                                                                                                                                                                                                                                  
                                                                                                                                                                                                                                                                                           
  If you're building/evaluating an agent scaffold, the transferable ideas are: (1) linear-message history as the trajectory of record; (2) control flow via message-carrying exceptions rather than flags/state machines; (3) single bash tool + stateless subprocess execution for        
  sandbox/scaling; (4) prompts-as-config so benchmark tuning is data-driven; (5) bounded, informative format-error recovery.                                                                                                                                                               
                                                                                                                                                                                                                                                                                           
  One caveat worth flagging: its strength is benchmark performance with a strong model in a bash-only setting. For interactive daily-driver use it's deliberately minimal — no persistent shell state, no fine-grained file tools, single-action-per-step. So "learn from it" works best   
  if you adopt the architecture (linear history, exception-driven flow, config-as-data) rather than literally dropping to bash-only in a context that needs richer tooling.
